# L103MotorControl —— CH32L103 关节电机上位机 (Qt)

给 CH32L103 + DRV8316C / DRV8313 关节电机固件配的
CH32L103 + DRV8313 关节电机固件配的 Windows 图形上位机。**CAN 口与 UART 口两条通道都走**，
参数全用下拉框 / 复选框 / 数字框，不用手敲 hex。

2026-10-06 加了**「波形」页**：把板子流出来的三相相电流画成实时曲线（走 UART，9 B/帧）。

2026-10-16：动作键**不再弹确认框**（原来那张框里的"当前/目标/要走多少圈"整段改写进日志页），
并且**每次动作前无条件先自动使能**（走位 / 连续转 / 回机械原点 / 跑脚本；「对齐」例外）。
详见 `docs/使用说明.md` §3.4。

2026-10-16（同批, 多节点）：界面按**一条总线上挂多台板**重排 —— 顶上多一条「目标设备」条,
左边多一张**设备表**（自动认在线节点 / 点一行就切目标）, 序列页多一列**节点**,
一条序列可以**同时给多台装各自的段、再统一广播起跑**。详见 `docs/使用说明.md` §3.2、§3.5。

这一步跟着固件的 CAN 协议改动走：**CAN ID 里从此带节点号**
（`ID = (节点号 << 5) | 功能号`, 节点号 0 = 广播、1..63 = 设备地址）。
**老的固定 ID（`0x100` / `0x110` / `0x120`…）已作废** —— 本上位机与老固件互不通用。

2026-10-23：**「L103 调参」页签**现在把使能 / 失能·松轴 / 对齐 / 清故障、以及**速度模式的启动与停止**
直接放在参数表下面（含一行状态「已使能 · 已对齐 · 运行中 · 堵转」），不用为了一次操作来回换页签；
参数名/单位改成**按板型选表**（L103 的 16 项不再套 V303 的 27 项）。速度给定上限放到 ±99999 rpm，
超过角度环上限只在日志里提示，钳位交给固件的 `vel_limit`。
程序**带图标**（齿轮 + 电机，`src/app.ico`，`RC_ICONS`）。详见 `docs/使用说明.md` §3.6 与 §3.6.1。

## 它解决什么问题

以前调这台电机是在串口助手里手敲 `G1.8888@600`、`*{0,60,90,0}{1000000,-60,90,0}`
这类命令，还得自己算 CAN 的 8 字节小端打包。手敲错一个字段，机构真的会跑飞
（2026-09-28 那次 `G` 参数误用，电机实跑 131 圈）。这个程序把命令表做成了界面。

## 编译与运行

需要 Qt **5.14.0 MinGW 64**（`C:\Qt\Qt5.14.0\5.14.0\mingw73_64`，含 `Qt5SerialPort`）。

```powershell
pwsh -NoProfile -File scripts\build.ps1     # qmake + mingw32-make
pwsh -NoProfile -File scripts\deploy.ps1    # 把 Qt 运行时 DLL 拷进 build\
build\L103MotorControl.exe
```

**注意**：本机 `windeployqt` 报 `Unable to find the platform plugin.` 且一个 DLL 都不拷，
所以 `deploy.ps1` 是手工拷的（Qt5Core/Gui/Widgets/SerialPort + `platforms\qwindows.dll`
+ libgcc_s_seh-1 / libstdc++-6 / libwinpthread-1 + USBCANx64.dll）。别改用 windeployqt。

## 协议速查（源码逐条核过）

CAN（全小端, **11 位标准帧**, 1 Mbps）：

```
ID = (节点号 << 5) | 功能号          节点号 0 = 广播(所有节点), 1..63 = 设备地址
```

> 下表写的是**功能号**；发到节点 n 就是 ID `(n<<5)|功能号`。
> 例：节点 2 的「使能」= `(2<<5)|2` = `0x042`；广播走位 = `0x000`。

| 功能号 | 方向 | 作用 | 载荷 |
|---|---|---|---|
| 0 | 主机→板 | 位置/速度(PV) | b0-3 目标 mrad(i32)；b4-5 速度上限 ×0.01rad/s；b6 flags；b7 保留 |
| 1 | 主机→板 | 纯速度 | b0-1 目标 ×0.01rad/s；b2 flags |
| 2 | 主机→板 | 使能/失能 | b0 1=使能 / 0=失能 |
| 3 | 主机→板 | 回机械零 | b0-1 速度上限 ×0.01rad/s（0=默认） |
| 4 | 主机→板 | 设当前为机械零 | —（立即存 Flash） |
| 5 | 主机→板 | 询问 | b0 0=位置速度 1=配置 2=故障 3=电机参数 0xFF=四帧全回 |
| 6 | 主机→板 | 故障上报配置 | b0 开/关, b1 周期 ×100ms |
| 7 | 主机→板 | 角度环速度上限 | b0-1 ×0.01rad/s |
| 8 | 主机→板 | 电机参数(写 Flash) | b3 bit0 必须=1 |
| 9 | 主机→板 | 动作脚本: 加一段 | b0-1 等待 ×100µs(u16)；b2-3 ±rpm(i16)；b4-5 角度 ×0.1°(i16, 上限 **3276.7°**)；b6-7 停留 ×10ms(u16) |
| 10 | 主机→板 | 动作脚本: 控制 | b0 0=清空 1=开始 2=打印；b1=遍数 |
| 11 | 主机→板 | 加一段 · **大角度版** | 布局同 9, 但角度刻度 ×**1°**（上限 32767°）—— 超 3276.7° 的段自动走这条 |
| 12 | 主机→板 | 设节点号 | b0=节点号 1..63；b1=`0x5A` 防呆（**别广播发**） |
| 16..21 | 板→主机 | 反馈 | 16 周期反馈(默认不发) / 17 即时状态(询问应答兼 ACK) / 18 配置 / 19 故障 / 20 电机参数 / 21 故障事件 |

**应答帧里带的是"答话那台自己的"节点号** —— 广播问一句, 多台同时回也不会撞车, 上位机分得清是谁。

功能 0 的 flags：bit0 相对 / bit1 运行(**bit1=0 即停止**) / bit2 松轴 / bit3 清故障 / bit4 存 Flash / bit5 机械坐标。

**节点号怎么设**：串口 `%` 看、`%3` 设成 3 号（存 Flash）；或 CAN 功能 12（`b0=号, b1=0x5A`）。
新板出厂默认 1。**别用广播发功能 12** —— 在场还是默认号的板子会一起被改成同一个号。

### 参数表（2026-10-22 加，功能 15 / 回 23）

「参数」页最上面那张参数表，就是板子里的电机参数表（存 Flash，上电在电机跑之前读回来）；
行数以板子 INFO 回报的个数为准（2026-10-23 固件是 35 行），不是上位机写死的。
一帧一个参数。**不用功能 8**：8 号是 L103 老板的"极对数/堵转/母线"三项老格式，留着给老板用。

```
主机→板  (节点<<5)|15:
  b0 = op   0 INFO / 1 READ / 2 WRITE / 3 SAVE / 4 DEFAULTS / 5 RELOAD
  b1 = 索引(READ 时是起始索引)
  b2 = READ 时的个数(0 当 1)；其它 op 时 b2..5 = float 小端
  b6 = 0x5A （写 / 存 / 默认 / 重载必须带）
板→主  (节点<<5)|23:
  b0 = op|0x80   b1 = 索引(0xFF 个数 / 0xFD 存盘 / 0xFE 重载 / 0xFC 默认值)
  b2..5 = float 小端
  b6 = flags  bit0 Flash 有有效记录 / bit1 改过没存 / bit2 本帧失败
  b7 = 0xA5 签名
```

读全表 = 先发 INFO（`op=0x00`）问板子参数个数（应答 `index=0xFF`、`value=个数`），
再 READ 一次 `b2=个数`，板子回同样多帧（板侧走发送队列，每次主循环只发一帧）。
**写进板子只进 RAM、立即生效；要掉电保存得再按「存 Flash」。**
改坏了按「恢复出厂默认」再「存 Flash」；想丢掉 RAM 里的改动就「从 Flash 重载」。

`kParamName[] / kParamUnit[]`（`mainwindow.cpp`）按索引当字典用，必须与固件 `MotorCfg_Name()/Unit()` 同序同名；
表有几行以板子 INFO 回报的个数为准（不再写死 `PARAM_COUNT`），查不到的名字显示 `idx NN`。

UART（115200 8N1，行尾 `\n`）：`E` 使能、`D` 失能、`B` 停+保持、`B1` 停+松轴、`O` 清故障、
`F` 设机械零、`N` 回机械零、`A` 对齐、`M1` 速度环、`G<圈>@<rpm>` **绝对圈数**、
`*{等待µs,±rpm,角度°,停留ms}` 脚本（`*0` 只清队列，停不下来正在跑的，要用 `B1`）、
`SW`/`SW1`/`SW0`/`SWD<div>`/`SWB<baud>` 相电流波形流（波形页用，子命令名不区分大小写）。

**`G` 是绝对目标位置、单位是圈，且 `Motion_RunPV()` 不做任何行程校验** —— 想小幅度试，
先读当前位置、按绝对口径取一个贴住当前值的目标，别直接填小数字。

## 已知限制（未验证项，接手前先看 docs/使用说明.md 的清单）

- **多节点这条（2026-10-16 的节点地址改造）没上机**：固件编过、上位机离屏自测过,
  真总线上挂 2 台以上还没试（板子回来才验证）。步骤见固件仓库
  步骤见固件 `docs/` 下的多节点说明。
- **老上位机 / 老脚本与本版固件不通用**：按 `0x100` / `0x110` 发的老帧, 在新固件里会被当成"别的节点"的帧丢掉。
- **多节点脚本不是硬时间同步**：多台各按"共享时间表 + 相对等待"跑; 某一段超时, 那一台整体顺延（各台之间会有漂移）。
- **物理层**：本板 CAN 端子上 `R12 = 120 Ω` 是**焊死的**。挂多台时**只有总线两端各留一个 120 Ω**,
  中间节点的 `R12` 要拆掉; 星形接线不行（MAX3051EKA+T 手册要求手拉手一条线到底）。
- **UART 这条 2026-10-06 已联调通**（状态刷新 / 使能 / 转速 / 波形流收发停，都在真台子上跑过）。
- **CAN 这条 2026-10-06 已验通**（CH9433 枚举 / 打开 / 收帧 + `0x100` 走位载荷按 30 度量级），依据见 `docs/使用说明.md` §5。
  但那两次跑的是**老固件的老 ID**。2026-10-16 换成「节点号 << 5 | 功能号」之后, 收帧解析那段代码没动, 但**新的 ID 口径没上机验过**。
- **参数表（功能 15/23）2026-10-22 已上机验通**（CH32V303 5010 关节板，节点 1，1 Mbps）：
  读全表 27 项、写单项回读、存 Flash 后断电重上电仍是新值、恢复出厂默认 —— 都在真板子上跑过。
  （2026-10-23 起固件参数表加到 35 项；GUI 已改成按板子 INFO 回报的个数建表，不再写死 27。）
- 达妙 DM-USB2CAN 的 30 字节信封本机没有卡，**没测过**。
- 波形页的**母线 I/V 是灰的**：本版硬件没有母线采样通道（`VM_SENSE_ENABLE=0`），下一版 PCB 再接。
