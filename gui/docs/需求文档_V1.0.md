# L103 关节电机调试上位机 —— 需求文档 V1.0

| 项 | 内容 |
|---|---|
| 版本 | V1.0 |
| 定稿日期 | 2026-10-24 |
| 适用程序 | `gui/`（Qt 5.14.0 / MinGW 7.3 64 位，可执行 `build\L103MotorControl.exe`） |
| 对端 | CH32L103K8U6 + DRV8316C + MT6701 关节驱动板（固件 `CH32L103_DRV8316C_FOC_V2`）；兼容 2026-10-15 及更早的旧协议固件 |
| 使用者 | 台架调试人员，以及后续接手这块板的人 |
| 需求来源 | 2026-10-05 ~ 2026-10-24 的逐条需求，落在版本记录与工作记录里 |

> 这份文档回答一个问题：**界面为什么长成现在这样。** 每条需求都写了「当初的需求 / 为什么 /
> 最后落成什么样子」，方便下一版重做界面时不要把手感丢掉。

---

## 1. 这是什么

一块关节电机驱动板（L103 + DRV8316C + MT6701）的**调试上位机**：不写代码、不烧固件，就能把电机
转起来、把参数改掉、把位置走到、把相电流画出来。

它**不是**产品固件的一部分，也**不是**给最终用户用的界面 —— 它是台架上的扳手。

## 2. 三条总原则（先看这三条，再看细节）

### 2.1 中间商原则（2026-10-23 定）

> 需求：上位机只是下发指令的控制软件，不承担业务逻辑，不替使用者做决定。

- 按钮点了就发命令，**不替人判断**"该不该发""要不要改成别的发法"。
- 板子拒绝就把拒绝照原样显示出来，不偷偷兜底、不自动改道。
- 推论：界面上任何"智能"行为都必须能被使用者看见（写进日志），且能被关掉。

### 2.2 一条总线多台（2026-10-16 定）


- 固件只有一路 CAN（`board.h`: CAN1 = PD0/PD1，收发器 MAX3051EKA+T），所以"多设备"只能
  **一条总线挂多台**。
- 编址：`CAN ID = (节点号 << 5) | 功能号`，节点号上限 63。
- 界面必须有"目标设备"这个概念：现在在指挥谁、这条命令会发给谁。

### 2.3 参数必须能在界面上改完（2026-10-05 定）

- 需求：把 CAN 指令都收进一个 Windows 应用，参数用下拉框 / 复选框 / 数字加减框实现；CAN 与 UART 两种通道都要。

- 换一种电机只改参数表，**不改代码、不重编固件**。
- 参数用控件（下拉框 / 复选框 / 数字框），**不让人手敲命令**，少一个手误的机会。
- 但"手敲"这条后路要留着（「日志 / 原始」页），因为调试时总有界面没覆盖到的组合。

## 3. 需求清单

编号规则：`R-xx`。每条写四件事：**要求 / 出处 / 为什么 / 落成什么样**。

### 3.1 通信

**R-01 双通道：CAN + UART，二选一，能自动挑**

- 出处：2026-10-05 初次需求（"要 can 口和 uart 口两种"）。
- 为什么：CAN 是台架主通道（CH9433 EVB / 达妙 USB-CAN）；串口 `COM15 @115200` 是兜底 ——
  CAN 收发器烧过（2026-10-06 家人："9433 烧了，我在修"），那时全靠串口把活干完。
- 落地：顶部选口区；两个都开着时动作优先走 CAN（能表达相对/机械坐标），UART 作后备。

**R-02 新旧两代 CAN 协议并存，自动识别**

- 出处：2026-10-23「对齐/使能不起作用」定位 —— GUI 发新 ID（`节点<<5|功能号`），
  板上是 10-15 的旧固件（固定 ID `0x110/0x113`），一条都不认。
- 为什么：手上有好几块板，固件版本不齐；不能因为 GUI 升级就把旧板扔了。
- 落地：「协议」下拉（自动 / 新 / 旧）；开 CAN 后发**只读**问询，谁回音锁谁；
  1.5 s 一帧没收到就在日志里直说"CAN 线/收发器不通，或节点号不对"。

**R-03 节点扫描 / 广播 / 单点**

- 出处：2026-10-16 多节点重排。
- 为什么：一条总线上多台时，要能"看现在有谁在线""这条命令是发给所有台还是某一台"。
- 落地：目标设备条（节点号 + 协议 + 状态）、扫描按钮、广播开关。
  **广播下禁止改台子状态的命令**（设机械零点、写参数、改节点号）—— 这条是安全，不是业务逻辑。

### 3.2 状态与观测

**R-04 一眼看到板子现在什么状态**

- 出处：2026-10-05 初版；2026-10-18 补板型/固件版本。
- 为什么：调参时最常问的三件事是"它使能了吗""它对齐了吗""它为什么不动"。
- 落地：「状态」页 + 顶部常驻条：`mode / en / al / flt`、位置、速度、`iq/id`、母线电压、
  板型、固件版本、故障累计。
- 显示口径：位置同时给**机械坐标**和**原始坐标**（差一个零位，混一次就差几十度）。

**R-05 相电流实时曲线**

- 出处：2026-10-06 家人原话：**"把相电流实时取出来, 通过 can 口或者调高 uart 的速率送出来,
  然后在那个 qt gui 上实时画出来, 预留一个母线电流和电压, 下一版 pcb 回来后我们就都有了"**。
- 为什么：FOC 调没调好，看波形比看数字快；堵转、失步、相序错，波形一眼能认出来。
- 硬约束（同一条需求里给的）：**"不要影响 FOC"、"也不要影响电机的正常运转, 这是前提, 一切给它让路"**。
  所以上行必须非阻塞（固件侧 `SW` 命令 + 9 字节帧），GUI 这侧只管收。
- 落地：「波形」页，自绘曲线（本机 Qt 没装 QtCharts）。

**R-06 日志 / 原始页：每条命令和回显都要看得见，还能手敲**

- 出处：长期使用中反复要（调试时"你看着串口的返回"）。
- 为什么：出问题时第一现场是回显；而且界面没覆盖到的命令要能直接发。
- 落地：一条一行，带时间；原始页可直接输入任意命令。

### 3.3 参数

**R-07 参数表 = 固件 `motor_cfg` 的全部调参量**

- 出处：2026-10-05 需求；2026-10-23「参数表按板子回报项数」。
- 为什么：不同板型参数个数不同，表写死就会错位。
- 落地：**行数以板子回报的个数为准**，多一行少一行都不行；带说明列（2026-10-22）。

**R-08 四个动作分开：写 RAM / 存 Flash / 从 Flash 读 / 擦除**

- 出处：2026-10-05 起就有；2026-10-23"为啥写 flash 不起作用 重新读取后 还是原来的值"。
- 为什么：**写 RAM 立刻生效但断电就没**，存 Flash 才留住；两者混在一起，人就会以为"我改了它没记住"。
- 落地：四个按钮分开，按钮旁边写清后果；`SAVE` 会擦一页 Flash（手册典型 6.2~7.5 ms 擦除 +
  2.0~2.5 ms 编程），期间控制环会丢几拍，提示别在运动中点。

**R-09 写 103 和写 303 不是同一个 Flash**

- 出处：2026-10-23：写 L103 和写 CH32V303 要区分开，两者不是同一个 Flash。
- 为什么：手上有 L103 和 CH32V303 两种板，参数页布局/地址不同，混着发会把别人的参数写坏。
- 落地：按板型分表、名字分开取；参数表里写明这是哪块板的。

### 3.4 动作

**R-10 电机动作按钮：使能 / 失能 / 停 / 清故障 / 设零点 / 回零 / 对齐 / 重标电流零点**

- 出处：2026-10-05 起；2026-10-18 对齐改走 CAN 功能 13；2026-10-19 回机械 0 点按钮。
- 为什么：这是台架上 90% 的操作。
- 落地：「动作」页 + 「L103 调参」页各一套（见 R-14）。

**R-11 停 = 停 + 失能，不在原地顶住**

- 出处：2026-10-23：停不下来时要停止它，不要试图恢复到什么位置。
- 为什么：停的时候还在闭环顶住，人手动掰轴会被电顶回来，也容易发热。
- 落地：`B0` / `B1` 一律"停 + 桥臂高阻"。

**R-12 清故障只清故障：不动机构、不重新使能、不恢复位置**

- 出处：2026-10-23：清故障就是清理，不恢复位置。
- 为什么：清故障是"把锁存位清掉"，不是"把机器恢复到某个状态"。后者会突然动，危险。
- 落地：`X` 只清故障；界面上没有 `O` 那条命令。

**R-13 动作前自动使能；但「对齐」不插使能**

- 出处：2026-10-16 的需求（去确认框 + 动作前自动使能）。
- 为什么：没使能就发目标，目标会挂在那儿，之后一按使能就冲出去（实测冲过约 18 圈）。
- 落地：走位/速度/回零前先发使能；对齐例外（固件自己会合闸）。

**R-14 L103 调参页签要能一站式操作**

- 出处：2026-10-23：把使能 / 失能 / 对齐放到「L103 调参」页签下，避免来回切页；随后追加把速度模式的启动 / 停止也放到该页签。
- 为什么：调参时人盯着参数表，动一下就要切页签，很低效。
- 落地：「L103 调参」页顶部加一行 `使能 / 失能 / 对齐 / 清故障` + 状态标签；
  再一行 `速度模式 [rpm] 启动 / 停止`。

**R-15 数值上限统一放到 99999**

- 出处：2026-10-23：速度模式上限放到 99999，其他数值同样。
- 为什么：调试时不想被界面的框限制住（真正的保护在固件侧）。
- 落地：速度给定 ±99999 rpm；同类数值框一律 99999。

**R-16 保护参数也要能调（堵转电流 / 堵转时间）**

- 出处：2026-10-23：堵转不到 1 A 就跳闸，保护参数也要放到界面上；并追加堵转时间 5 秒可调。
- 为什么：保护值不合适会把正常动作判成堵转，只能在界面上快速改、边看边调。
- 落地：堵转电流、堵转时间两个输入框，写进固件参数表。

### 3.5 界面与手感

**R-17 字体大两号**

- 出处：2026-10-23：字体调大 2 号，原来看着累；调整后确认舒适。
- 落地：全局字号在初版基础上 +2。

**R-18 应用图标：齿轮 + 电机**

- 出处：2026-10-23：给应用加一个包含齿轮和电机的图标。
- 落地：`src\app.ico`（齿轮 + 电机），编进 exe。

**R-19 布局不要憋**

- 出处：2026-10-24 **"框都太密了 稍微拉开点距离"**。
- 为什么：一屏里控件太挤，看久了累、也容易点错。
- 落地：加大布局 spacing 与 margins（见 `工作报告_2026-10-24_GUI间距`）。

**R-20 中文界面，术语按台架说法**

- 出处：全程。
- 为什么：台架上的词是"使能/失能/对齐/回机械 0 点/清故障"，不是 enable/disable。
  日志里的每个字段都要能对上串口回显（`pos=` / `vel=` / `flt=`）。

### 3.6 与固件配套的口径

**R-21 机械零点：设完存 Flash，停稳 3 s 自动写**

- 出处：2026-10-23 **"机械0点要保存在flash中, 运动停止后3秒以上就要写一次当前位置,到flash中,
  不要在foc中写flash … 只有完全停止不动了3秒以上才可以写"**。
- 为什么：零点丢了整台机器的坐标就废了；但不能在动的时候写（擦一页会打断控制环）。
- 落地：GUI 只负责发 `F` / 功能 4；写盘由固件做。界面文案与提示都按这个口径写，
  不再出现"只在本机上电期间有效"这种旧说法。

**R-22 停/走/回零的单位与坐标口径必须写死并显示**

- 出处：2026-09-28 的 `G` 参数事故（把圈当弧度），以及 2026-10-06 的"越走越远"。
- 为什么：同一个数字，理解成圈还是弧度差 6.28 倍；机械坐标还是原始坐标差一个零位。
- 落地：走位区明确标单位（圈 / 度 / 弧度）、明确标"机械坐标"勾选；
  下发前日志里把"当前位置 / 目标 / 要走多少"都打印出来。

## 4. V1.0 的界面结构

七个页签，按"从看到动、从动到调、从调到查"的顺序排：

| # | 页签 | 放什么 | 为什么在这一页 |
|---|---|---|---|
| 1 | 状态 | 实时量、故障、板型/固件版本、节点在线情况 | 打开就要看的第一眼 |
| 2 | 动作 | 使能/失能/停/清故障/设零点/回零/对齐 + 走位(PV) + 速度模式 + 连续转 | 手最常点的地方 |
| 3 | 序列 | 板载脚本（多段、遍数、绝对/相对） | 重复动作不必手点 |
| 4 | 参数 | 固件参数表 + 写 RAM / 存 Flash / 读取 / 擦除 | 改参数是"整张表"的活 |
| 5 | L103 调参 | 参数表 + 使能/失能/对齐/清故障 + 速度模式启动/停止 | 调参时不用来回切页签（R-14） |
| 6 | 日志 / 原始 | 每条命令与回显、直接敲命令 | 出问题的第一现场 |
| 7 | 波形 | 相电流曲线 | 判断 FOC 好不好 |

顶部常驻：串口/CAN 选择、目标设备（节点 + 协议 + 状态）、连接状态。

## 5. 交互约定

1. **每一步都留痕**：按钮按下、发了什么、板子回了什么，全进日志。
2. **危险动作要标出来**：对齐会硬拽转子、`SAVE` 会擦 Flash、走位 > 1 圈会标 `★`
   —— 标出来，但**不拦**（R-11 之后统一成这个口径）。
3. **拒绝要说得清**：板子回 `ERR` / `REJECT` 时，日志里写人话（"还没设机械零点，先按 F"）。
4. **数值显示带单位**，且和固件回显字段对得上。
5. **不弹无谓的确认框**（2026-10-16 起）：确认框只留给"会写 Flash / 会动机构"的极少数操作。

## 6. 非功能需求

- **运行环境**：Windows 10/11 x64；Qt 5.14.0 MinGW 7.3 64；随 exe 部署 Qt 运行库。
- **构建**：`qmake ..\L103MotorControl.pro -spec win32-g++` + `mingw32-make -j8`；
  产物 `build\L103MotorControl.exe`。
- **可移植**：工程里不许留绝对路径。
- **仓库**：本仓库，工作区 = 工程目录本身。

## 8. 已知限制 / V2 想做的事

1. **界面还是"能用"级别**：控件是功能区堆出来的，没有视觉层级、没有深色模式、没有自适应缩放。
2. **一屏信息量大**：2026-10-24 拉开间距后窗口 1676 x 1288，最小高度 1288 px ——
   左边那块 1080p 屏（工作区 1032 px）放不下，会露底；主屏 2560x1440 刚好。
   要常年放小屏，得把纵向间距再收，或者把参数区做成可滚动。
3. **波形只画相电流**：母线电压/电流的预留位有了，等下一版 PCB。
4. **多台真机联调**：两台以上的总线联调还没在真台上跑全（2026-10-16 时板子还在焊）。
5. V2 的方向（未开工，先记着）：分栏（左导航 + 右工作区）、状态常驻条、把"调参"和"动作"
   合成一个工作台、参数表支持搜索/分组/一键恢复默认、波形支持叠加与游标。
