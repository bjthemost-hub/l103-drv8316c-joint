# L103 关节电机调试上位机 —— 使用说明

CH32L103 + DRV8316C FOC 台架的上位机（**一条 CAN 总线上可以挂多台**, 每台一个节点号）。把手工敲的 CAN / UART 命令做成界面,
参数一律用**下拉框 / 复选框 / 数字加减框**。CAN 口和 UART 口两条路都支持。

写这份东西的日期: 2026-10-05，**2026-10-16 按「多节点 CAN」重排过界面**（见 §3.2）。命令语义一律以**固件侧权威材料**为准:

- `firmware/docs/命令表.md`
- 同工程 `firmware\CH32L103_DRV8316C_FOC_CAN\User\` 下的源码(`can_bus.c` / `can_bus.h` / `cmd.c` / `motion_pv.c` / `board.h` / `faults.h`)

> ⚠ **2026-10-16 起 CAN ID 里带节点号**: `ID = (节点号 << 5) | 功能号`
> （节点号 0 = 广播, 1..63 = 设备地址）。老的 `0x100` / `0x110` / `0x120` 这套固定功能 ID **已作废** ——
> 本上位机只认新口径, 与 2026-10-16 之前的老固件**互不通用**。本文里凡是写「功能 N」的地方,
> 发到节点 n 就是 ID `(n<<5)|N`（例: 节点 2 的走位 = `0x040`, 广播走位 = `0x000`）。

源码 > 命令表 > 记忆。界面上每条按钮的 tooltip 里都写了它发的是哪条命令。

## 3. 界面怎么用

窗口从上到下三段: **连接条** → **目标设备条** → 左右分栏（左 = **设备表**, 右 = **页签**）。
默认开 1660×900; **实测窗口最小 1577×804 px**（右边那些页签的最小宽度 942 px 顶着, 见 `docs\工作报告_2026-10-16_多节点上位机重排.md`）—— 再窄就摆不下了。
中间那条分隔线是**能拖的**: 想看设备表的哪一列, 往右拖一点。
两条通道( UART / CAN )可以同时开;
**两个都开着时, 动作类命令优先走 CAN**(功能 0 的表达力比 UART 的 G 强: 能相对、能机械坐标)。

### 3.1 连接条

| 控件 | 说明 |
|---|---|
| UART 控制台 | 端口下拉 (默认自动选 COM15) + 波特率 (默认 115200 8N1) + 刷新 + 打开 |
| CAN 类型 | `关闭` / `沁恒 CH9433 EVB (裸帧)` / `达妙 DM-USB2CAN (30B 信封)` |
| CAN 设备 | CH9433 时列出 DLL 枚举到的设备; 达妙时列出串口 |
| CAN 速率 | CH9433 给的是 CAN 位速率 (1 Mbps 等); 达妙给的是串口波特率 (921600) |

打不开的常见原因:

- UART: **COM15 被 SSCOM 之类的串口工具占着** —— 先关掉那个工具。
- CAN(CH9433): MI_00 被 **USBCanDemo.exe 独占** —— 先关掉它。

### 3.2 目标设备条 · 设备表（多节点用）

**目标设备条**（连接条下面那条）决定"命令发给谁":

| 控件 | 说明 |
|---|---|
| 节点（数字框） | `0 = 广播 (所有节点)`, `1..63` = 某一块板的地址。动作命令的 ID = `(节点 << 5) | 功能号` |
| 协议（下拉框） | `自动` / `新 (节点<<5)` / `旧 (0x110/0x113)`。**2026-10-23 新增**，见下一段 |
| 扫描节点 | 先清空设备表, 再广播发一发**功能 5**（询问, `b0=0xFF`）—— 在线的每一台都会用自己的节点号回一帧 |
| 节点信息 | 一行字: 选单节点时报「节点 N · 状态 · 收帧数 · 最近一帧多久前 · 机械多少圈 · **板型 / 固件版本**」; 选广播时报「发现 N 台, 在线 M 台」 |

#### 协议：两代固件都能用（2026-10-23）

板子上的固件有两代 CAN 地址，**载荷逐字节相同、只有 ID 不同**：

| | 使能 | 询问 | 对齐 | 板型/版本 |
|---|---|---|---|---|
| **新**（2026-10-16 起，如 `cd8beb9`） | 功能号 2 → `0x022` | 功能号 5 → `0x025` | CAN 功能号 13 → `0x02D` | 功能 14/22 |
| **旧**（2026-10-15 及以前，如 `e3e0f5c`） | 固定 ID `0x110` | 固定 ID `0x113` | **没有**，只能串口 `A` | 没有 |

- **自动（默认）**：打开 CAN 后 300 ms（以及每次点「扫描节点」）把**只读**问询两套各发一帧
  （新 `0x05`/`0x0E` + 旧 `0x113`），收到哪一套的回音就把协议锁到那一套，日志里会写
  `[协议] 认出来了: …`。「节点信息」末尾也会显示 `旧协议(≤10-15)` / `协议待探测`。
- **不会双发动作命令**：旧 ID `0x100..0x1A0` 在新协议里会被算成节点 8/9/12/13 的功能号，
  总线上一旦真有那个节点，双发就等于给它下命令。所以动作命令只按锁定/手选的那一套发。
- **旧协议 + 点对齐**：旧固件没有 CAN 对齐，程序会自动改走串口 `A`（`UART 控制台`必须已打开, 115200）。
  串口没连就弹框提示，不会静默失败。
- **1.5 s 一帧回音都没有**：日志会直接写「CAN 线/收发器不通, 或板上节点号不是 N」。


板型那一截是 CAN **功能号 14**（读板型/固件版本）问来的，板子用**功能号 22** 回 8 个字节：
`b0` 板型号（1 = `L103 + DRV8316C`）、`b1..b3` 固件 主/次/修订、`b4` CAN 协议版本。
打开 CAN 后自动问一次（延迟 300 ms），点「扫描节点」也会顺手问一遍；没答出来就显示「板型未知」，不影响任何操作。
板型号是**两边约定**的数，不是从板子上读出来的名字 —— 以后每加一款板往后加号，老号不许改。

**设备表**（左边那张 6 列的表格）是"这台板多久没吱声"的账本 —— 收到任何带节点号的帧都会刷新对应行:

- 列: 节点 / 在线 / 状态 / 位置(圈) / 速度(rpm) / 电流(A)。
  收帧数没单独占一列 —— 鼠标停在那一行上会显示, 上面「节点信息」里也有。
- **在线判定 = 5 秒内听到过**（`DEV_ONLINE_MS = 5000`）。这是"我多久没听到你", **不是"你坏了"** ——
  板子在失能状态下不主动发帧, 所以静下来 5 秒很正常, 别拿它当故障指示。
- **点设备表任意一行 = 把「目标设备」切到那一台**, 右边各页的读数跟着换成那一台的。
- 每台的状态**分开存**: 切走再切回来读数还是那一台的（不会串台）; 没数据的节点显示空白, 不会留着上一台的读数。
- 表每 0.5 秒 (2 Hz) 自己刷一遍。
- 「立即刷新」/「自动刷新」在 CAN 下默认发**广播**询问 —— 一次把所有在线的台子都问一遍;
  勾上那句「只轮询『目标设备』那一台」才改成单播（总线安静时用）。

> **广播 = 每一台都执行。** 所以「设机械零点」「写电机参数」这类**改台子状态**的操作在广播下会被拦下来,
> 要你先选到具体某一台。动作类命令（走位 / 转 / 回零 / 跑脚本）**允许**广播 —— 那本来就是让所有关节一起动。

### 3.3 状态页

只读。显示机械坐标 / 位置 / 速度 / 相电流 / 状态位 / 配置 / 活动+锁存故障 / 电机参数 / 脚本进度。

- **立即刷新**: CAN 开着就发 **功能 5**（`b0=0xFF`, 一次问回 4 帧; 默认广播, 勾「只轮询『目标设备』那一台」则单播）; 否则 UART 发 `S`。
- **自动刷新 (1 Hz)**: 每秒重复上面那一下。
- **诊断按钮组**: 13 个 UART 只读诊断命令 (W / Y / Q / I / R / K / KR / J / X0 / X1 / S0 / S1 / H),
  一条都不动机构。板子没接 UART 时按了只会在日志里写一行提示。

### 3.4 动作页

| 分组 | 按钮 | UART | CAN（功能号） | 广播下 |
|---|---|---|---|---|---|---|---|
| 使能·安全 | 使能 | `E` | 功能 2 `b0=1` | 可以 |
| | 失能/松轴 | `D` | 功能 2 `b0=0` | 可以 |
| | 停 (B0) | `B0` | 功能 0 `flags=0x00` | 可以 |
| | 停 (B1) | `B1` | 功能 0 `flags=0x04` | 可以 |
| | 清故障 | `X` | 功能 0 `flags=0x08` | 可以 |
| | 过流跳闸阈值/延时 (L103) | `O<A>[,<ms>]` | (CAN 没有, 走参数 16/17) | — |
| | 设机械零点 | `F` | 功能 4 | **被拦**（改台子状态, 得先选到具体某台） |
| | 重标电流零点 | `U` | (CAN 没有) | — |
| | 对齐 | `A` | 功能 13 `b0=0x5A` | 可以（每台各自对齐） |
| 回机械原点 | 回机械 0 点 | `N<rpm>` | 功能 3 | 可以 |
| 位置运动(PV) | 走位 | `G<圈>@<rpm>` | 功能 0 | 可以（所有关节一起走） |
| 速度运动 | 开始转 / 停 | `M1` + `V<rpm>` / `B1` | 功能 1 | 可以 |

（CAN 的 ID 由「目标设备」那个节点号算出来: 节点 2 的「使能」= 功能 2 → `0x042`; 广播 = 节点 0 → `0x002`。）

要点:

- **走位目标 = 三件东西**: 数值 + 单位下拉(圈/度/弧度) + 绝对/相对单选。
  - CAN: 绝对 → 原始坐标; 勾「机械坐标」→ 机械坐标(要先设过机械零点); 相对 → 相对按下那一刻。
    **ID 按「目标设备」那个节点号算** —— 节点 2 的走位 = `(2<<5)|0` = `0x040`; 广播走位 = `0x000` (每一台都走)。
  - UART: **G 只有「绝对 + 圈」**。选了相对 / 机械坐标会明确拒绝并告诉你怎么改。
- 「读当前位置 → 填目标」把目标框改成**贴住当前位置**的绝对值 —— 想小幅试一下就用它。
- **动作键不再弹确认框** (2026-10-16 按家人要求去掉) —— 按下就发。
  原来"目标离当前位置超过 1 圈 / 还没读到位置"会弹的那张框, 内容(当前 / 目标 / 要走多少圈)
  现在整段写进「日志 · 原始」页, 前缀 `[动作]`。**发之前自己扫一眼那行日志和「当前 → 目标」** ——
  UART 的 `G` 只有绝对圈数、固件对行程零校验, 2026-09-28 跑飞 131 圈那次就是这么来的。
- **每次动作前, 本程序会无条件先发一遍使能**(不看当前是不是已使能) —— 走位 / 连续转 / 回机械原点 /
  跑脚本都这样。动作走 CAN 就先发 功能 2 `b0=1`, 走 UART 就先发 `E`; 按动作键不用再先手点「使能」。
  - 例外: **「对齐」不插使能** —— 固件自己会合上驱动去拽转子; 对齐完把**此刻位置定义成机械 0 点**, 然后停在失能 (要动再点使能)。
  - 重复使能不会跳: 固件 `E`/功能 2 会先重读当前轴位再抱 (motion_pv.c 里 `tgt=ref=shaft_angle`)。
- 「当前 → 目标」那行会实时算差多少圈 —— 发之前先看它。
- 速度运动里 **UART 的顺序是 `E` → `M1` → `V<rpm>`**(`E` 会把 controller 拨回角度环, 所以必须排在 `M1` 前;
  角度环里直接发 V 会被 PV_HOLD 每拍覆盖)。

坐标口径 (2026-10-06 理清, 依据固件 `can_bus.c`, 台架实测):

- **原始坐标** = 固件 `shaft_angle`。**功能 0 不带「机械坐标」的载荷、以及 UART `G`, 用的都是它。**
- **机械坐标** = 原始 − `home`(本台架 `home = -0.8630 rad`; 功能 18 的 b0..3 报它)。
  状态帧(功能 17)报的是**机械坐标**, 不是原始角 —— 这一点 2026-10-06 才发现。
- 状态页现在分两行: 「机械坐标」和「原始坐标 shaft」; 「读当前位置 → 填目标」按当前模式填对应口径
  (相对模式填 0)。
- 相对/机械两种模式的**载荷里只放"增量"或"机械角"本身** —— 固件自己会加"收到命令那一刻的角度"/"零位"。
  载荷里再预加一遍就是加两遍 (2026-10-06 修掉的 bug: 相对模式原来发的是 `当前角+增量`,
  固件又加一次当前角, 于是按一次目标 = 2×当前角+增量, 轴越走越远; 而且 1 圈确认框当时比的是
  `载荷−当前角 = 增量`(小), 恰好把这颗雷躲过去, 不会拦)。

### 3.5 序列页 —— 板载动作脚本（支持多节点）（支持多节点）（支持多节点）

表格一行 = 一段, **五列**: **节点 / 等待 (us) / 速度 (rpm, ±=方向) / 角度 (deg, 正数) / 停留 (ms)**。

- **节点列留空 = 用「目标设备」那一台**; 填了号 (1..63) 就发给那一台。一页表里可以混着写多个节点。
- **角度模式下拉（2026-10-19 加）**: 默认「相对增量 (老方式)」——角度填正数、方向看 rpm 符号;
  第二项「绝对位置 (机械坐标)」——角度可以是负数, 表示机械坐标里的绝对角。
  绝对模式下上位机按**发命令那一刻的状态帧**把每条绝对角换算成"相对上一条落点"的增量, 再走原来那套帧,
  所以固件一行没改。换算要求该节点有状态帧、且 `|vel| <= 0.2 rad/s`; `遍数 > 1` 时会自动补一段
  "回到第一个目标"的增量(否则第二遍会从上一遍的落点接着走)。
- 界面会同时给出两种发法(`预览要发的内容` 里都能看到):
  - **UART**: `*0` → 若干行 `*{...}` → `*!<遍数>`。一行只放得下 ~128 字符, 超了自动拆行(分行是**追加**语义)。
  - **CAN**: 功能 10 `b0=0` 清队列 → 每段一帧 功能 9/11 → 功能 10 `b0=1 b1=<遍数>` 开始。
- CAN 每段角度字段上限: **功能 9 = 3276.7 度**(int16 x0.1)、**功能 11 = 32767 度**(int16 x1 度)。
  超 3276.7 度的段自动改走功能 11; 再大就**拆成多段**, 等待只放第一小段、停留只放最后小段;
  等待只放第一小段、停留只放最后小段; 等待 >6.5535 s / 停留 >655.35 s 会被钳位并在日志里提示。
- **每台的段数上限 16**(板载队列, `MOTION_SEQ_MAX_SEG`), 按节点分开算。
  某台拆完超过 16 段就**整条拒绝**, 并在预览里写明是哪一台超了 —— 不会静默只发一半。
- **「停止脚本」用的是 `B1` / 功能 0 `bit2`** —— `*0`(UART) 和 功能 10 `b0=0`(CAN) 只清队列,
  **不停正在跑的那一段**(实测坑)。停止一律**广播**发, 免得只停了一台。
- 开始跑的前提: **已对齐 + 已使能**, 否则板子回 `SEQ: refused - ...`。
  **使能这一半由本程序代劳**: 点发送时会先发一遍**广播**使能(`E` / 功能 2 `b0=1`), 再装段、起跑。
  顺序不能反 —— 固件 `Motion_SetEnabled(1)` 第一件事就是 `Motion_Seq_Abort()`。
- 脚本的每一段都是**相对本遍起点**的, 来回跑不会越跑越偏; 也**没有**「跑完自己回机械 0」这种段 ——
  要归零得由上位机在跑完后再发一条 `N` / 功能 3。

**多节点怎么发**（CAN, 本程序替你把帧排好）:

```
1) 广播  功能 2  b0=1                使能所有台
2) 对每个出现过的节点 n:
     功能 10  b0=0        -> 节点 n     清掉 n 的队列
     功能 9 / 11          -> 节点 n     每段一帧, 顺序就是表里从上到下
3) 广播  功能 10  b0=1 b1=<遍数>      所有台在**同一帧**上起跑
```

- 各台的时间轴起点 = 收到"起跑"那一刻, 所以**起跑是对齐的**。
- 这不是硬时间同步: 每台的 wait 是"共享时间表减掉自己上一段的结束时刻"算出来的,
  某一段比标称耗时长, 那一台后面的段**整体顺延**（各台之间会有漂移）。预览里也写了这句。
- 表里节点的**出现顺序**就是发帧顺序。实测（离屏自测）节点 2 两段 + 节点 3 一段 = 7 帧:
  广播使能 / 2 清队列 / 2 两段 / 3 清队列 / 3 一段 / 广播起跑。


### 3.6 参数页

- **电机参数(写 Flash)**: 极对数(0=不改) / 堵转阈值 A / 母线电压 V → UART `#<pp>,<A>[,<V>]`, CAN 功能 8。
  三项 0 就是不改; 越界(极对数 1..64, 堵转 0.1..3.0, 母线 8..36)本地先拦。
  写之前不再弹确认框 (2026-10-16 去掉), 明细进日志页。
  **改极对数会把「已对齐」作废 → 之后必须重跑对齐(UART 的 A, 或 CAN 功能号 13, b0=0x5A)。**
- **角度环速度上限**: CAN 功能 7(UART 没有对应的; UART 的 `L<volts>` 是相电压上限, 不是一回事)。
- **故障主动上报**: CAN 功能 6(UART 的 K0/K1 开的是 CAN 反馈帧, 不是这个)。
- **节点地址 (写 Flash)**: 把「目标设备」那一台改成 `1..63` 号 → CAN 功能 12 (`b0=号, b1=0x5A` 防呆)。
  **广播下会被拦** —— 用广播发这条会把在场所有还是默认号的板子一起改名。第一次编号建议走串口 `%<n>`。
  改完节点号, 那台板**从下一个上电周期起**才用新号（板子里是存 Flash + 上电时读）。

### 3.6.1 「L103 调参」页签 (2026-10-23 加)

一页放 L103 + DRV8316C 的全部可调参数，操作不用来回换页签。

- **参数名/单位按板型选表**: 功能 22 回报 `boardId=1` → L103 的 18 项；其它板型仍用 V303 的 27 项。
  以前 L103 也套 27 项表，从索引 1 起名字全错位（写着 `vel_ref_accel` 的其实是位置环 kp）。
- **四个参数按钮**: 从 Flash 读取 (CFG) / 写入 RAM / 存 Flash (SAVE) / 擦除 Flash (DFLT)，
  通道可选 UART 或 CAN（功能 15 写、23 读）。
- **电机操作**: 使能 (E) / 失能·松轴 (D) / 对齐 (A) / 清故障 (X)，右边一行状态
  「已使能/未使能 · 已对齐 · 运行中 · 堵转」。与「动作」页走同一批槽。
  - `清故障 (X)` **只清故障**: 不动机构、不重新使能。CAN 开着就走功能 0 的 flags bit3，
    否则走 UART 的 `X`（`cmd.c:387` `Motor_ClearFault`）。旧版写死只发 UART，只开 CAN 时点了没反应。
- **速度模式**: 给定 rpm（上限 ±99999，超出角度环上限只在日志里提示，钳位由固件的 `vel_limit` 做），
  「启动速度 (M1/V)」先使能再进速度环；「停止 (B1)」= 停 + 失能（桥臂高阻，轴可手转）。
- **过流跳闸 + 持续 (2026-10-23 晚加)**: 左边「过流跳闸」= 相电流阈值 A（0.50~4.50），
  右边「持续」= 连续顶住多久才关桥 ms（0~10000，默认 5000，0 = 一拍就跳）。
  固件参数索引 16 / 17，UART `O<A>,<ms>`。**注意**: 这 5 秒里电流是真的在过。
  它跟上面的「电流上限」（电流环给定上限）不是一回事：一个是关桥保护，一个是正常运行的限幅。
- **起步软硬看「加速度」**: 速度给定的斜坡 (rad/s²)。2026-10-23 从 3600 降到 300 后，
  实测确认起步"好多了"。要更软继续降到 200/150，改完点「存 Flash (SAVE)」。
- **界面的启动目录是 `build\`**，Qt 运行库已用 windeployqt 放在同一目录，
  直接双击 exe 即可，不需要先设 PATH。

### 3.7 日志 / 原始

- 上半是日志: 每条发出的命令 `»`, 每条收到的 `«`。CAN 帧会带 ID 名和 8 字节十六进制。
- **UART 原始命令**: 想发什么就发什么, 回车即发(自动补 `\r\n`)。界面上没做按钮的命令全走这里。
- **CAN ID / 数据(hex)**: 发任意标准帧, 例 `0x005` + `FF`（= 节点 0 广播 · 功能 5 询问）。数据最多 8 字节。

### 3.8 波形页 —— 相电流实时曲线 (2026-10-06 加)

只走 **UART** (波形流是固件从 UART1 出的, CAN 没有这条通路)。

- **开始波形** = 先发 `SWD<div>`(分频), 再把串口切成二进制模式(不再按行解析)并发 `SW1`;
  **停止波形** = 发 `SW0`, 等 300 ms 把固件发送缓冲里的残余吐完后切回文本模式。
- 帧格式 **9 字节小端**: `AA 55 01` + `iU, iV, iW` 各 int16 (**0.001 A/LSB**)。
  固件里 `iU = -(iV+iW)` 是反推的, 所以上位机拿 **`iU+iV+iW ≈ 0`**(容差 0.04 A)当校验,
  用来排「数据里恰好出现 AA 55 01」的误同步 —— 下面那行统计里的「误同步」就是这个计数。
- **分频** `SWD<div>`: 板子采样周期 500 µs, 标称帧率 = 2000/div。一帧 9 B,
  115200 下 **SWD2** 是能收全的工作点(实测 ~757 帧/s, 误同步 0)。`SWD1` 会丢帧。
- **窗口**: 曲线横轴画多少个点。只影响画面, 不影响接收。
- **显示**: iU / iV / iW 三路分别开关。iV 来自 **PA4 / V 相 INA240(U8)**,
  iW 来自 **PA1 / W 相 INA240(U10)**, iU 是反推的。
- **母线 I/V** 那个勾是**灰的**: 本版硬件没有母线电流/电压采样通道
  (`VM_SENSE_ENABLE=0`, `CS_VM_Available()=0`), 下一版 PCB 接上再点亮。
- **双击曲线**清峰值保持(峰值 = 画面上出现过的最大 |i|)。**暂停画面**只停画, 不停收。
- 下面一行统计是**上位机实收口径**: `实收 N 帧 · N 帧/s · 误同步 N · 杂散 N 字节`。
  跟板子 `SW` 打的 `frames` 对不上, 就是这段串口路上丢了字节。

**板子侧不受影响**(这是设计前提): 每帧只是往 2 KB 发送环形缓冲塞 9 字节就返回,
缓冲满就丢帧并计 `txdrop`, **不等、不中断 FOC**。2026-10-06 在 500 rpm 稳转下实测:
波形关 `loopmax=814 µs` vs 波形开 `809..832 µs`, 固件 `txdrop` 没涨。

三个使用上的坑:

- 波形流期间串口跑的是二进制, **日志页看不到文本回复** —— 停止后自动恢复。
- 波形流期间界面**会暂停自己的 1 Hz 状态轮询**(只走 UART 时), 免得 `S` 的 ASCII 回复混进帧流。
  CAN 开着时不动它(状态走 CAN)。
- 板子在**失能**状态下每秒会打一段 `FAULT/CAN/TICK` 状态行(`main.c:243`), 这坨 ASCII 会混进
  帧流, 表现为「杂散」每秒涨 ~700、帧率掉到 ~650。**使能之后自动静音**, 杂散归零。
  想拿干净数据, 先 `E`。

**高级: 板子串口波特率 (SWB)** —— 会把**板子**的 UART1 改成下拉里那个值, 上位机跟着重开这个口。
**本机实测 (2026-10-06): WCH-LinkE 的串口桥在 460800 上收不全** —— 想真提速得等 CH9433 修好,
走它的串口。固件里波特率不存 Flash, 板子复位就回 115200。

### 3.9 「回机械 0 点」不动的三种情况 (2026-10-19, 2026-10-23 更新)

按钮本身只是发 功能3 `0x111`(CAN) / `N<rpm>`(UART)。固件侧有三条会让人以为"按钮坏了"的路径,
GUI 现在都在日志里直接说清楚:

1. **没做电角度对齐** —— 固件 `Motion_GotoHome()` 不检查 `aligned`, 而里面调用的 `motion_runpv_internal()`
   发现没对齐就**静默 return**: 命令算"成功"、轴不动、连故障位都不置。板子每次上电 `al=0`,
   所以先按「对齐 (A)」。GUI 只在日志里提示一句 `al=0`, **不拦**。
2. **从没设过机械零点** —— 固件 `Motion_GotoHome()` 直接 `return -1`, 板上只发一个 1 s 的 `CMD_REJECT`
   脉冲, 不弹窗。2026-10-23 起零点跟着位置一起**掉电保存** (设一次之后重启仍然有效),
   只有从没设过、或者重烧/擦过 Flash 才会被拒。
3. **本来就在机械 0 点** —— 目标 = 当前, 不动是正常。

**2026-10-23 起: 上位机只当中间商。** 按钮写什么就发什么 —— 不再「没对齐就拦下」、
不再「已经在 0 点就跳过」、也不再「没设零点就偷偷改走 PV 绝对坐标」。固件拒了会把 ERR 回上来,
界面照原样显示。

另外: 「设机械零点 (F)」/ CAN 功能 4 现在**存 Flash** —— 设完立刻生效, 轴**完全停稳 3 s** 后
板子自己写一次当前位置, 下次上电自动恢复。运动过程中、或者正在跑业务 (`busy=1`) 时不写;
位置变化 < 0.01 rad 不重复写。详见固件 `docs\调参手册_2026-10-23_参数与送达路径.md` §3.E。
