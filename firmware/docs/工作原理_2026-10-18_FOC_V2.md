# CH32L103 + DRV8316C  FOC V2 —— 工作原理

> 写给接手的人。**这一版是 2026-10-18 按 AT32M416（mclib）的骨架重做的**，不是旧固件的补丁。
> 所有数字都标了出处：源码行号 / 手册 / 算术推导。**没有上过板**，凡"未实测"的都写明了。

## 0. 一句话

旧固件是"**电压模式** FOC，闭环跑在主循环里"；这一版是"**电流环 + 速度环 + 位置环，全部跑在
20 kHz PWM 中断里**"。低速抖的三个结构性原因（见 §1）都是靠换结构消掉的，不是靠调参数压下去的。

## 1. 旧固件为什么会抖（三条，都能在源码里指出来）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 闭环（速度/位置环）在**主循环**里跑，节拍随打印/诊断浮动 | `CH32L103_DRV8316C_FOC_CAN/User/main.c:221-225`（`Move(); LoopFOC();` 在 while 里） |
| 2 | **没有电流环**：速度 PI 的输出直接当 `voltage.q` 下发给 SVPWM | `foc_motor.c:270`（`current_sp = PID_Velocity(...)`）→ `:273`（`voltage.q = current_sp`）→ `:249`（`SetPhaseVoltage(voltage.q, ...)`） |
| 3 | 测速是**5 ms 固定窗口 + 零阶保持**：低速时更新率只有 200 Hz，而且是台阶 | `foc_sensor.c:343` `VEL_WINDOW_US = 5000u`；`foc_sensor.c:331` 注释"攒够窗口再更新一次，中间返回上一次的值" |

为什么这三条在低速最要命：反电势 ≈ 0 时，"电压 → 电流"的增益就是 `1/R`（随温度变、还叠死区），
电压环把这一点当成增益未知的环节去调；再加上主循环 1.0~1.6 ms 一拍（出处：
`docs/可行性分析_2026-10-16_MT6701走2Mbps串口跨L103传输.md:22` 那张表的三个来源）和 200 Hz 的
台阶式测速，环路本身就在制造抖动。

> 注意：2026-10-14 那轮把 `VEL_WINDOW_US` 收到 1000 µs，**6 个轴位里 3 个自激**（40.2 / 41.0 /
> 46.1 Hz，q_pp 10.9~11.2 V）—— 说明"测速窗口"只是把症状压住的旋钮，不是根因。
> 记录：`docs/注意事项_2026-10-14_保持抖动两条根因与测速口径.md` §1。

## 2. 新结构：三层节拍，全在 PWM 中断里

```
        TIM3 中心对齐 20 kHz（ARR = 96MHz/2/20k - 1 = 2399）  ← board.h:27-29
        每个载波周期两个 UEV：
          峰值 (CNT≈ARR)  →  Motor_PeakIsr()   : 起三相电流注入 + 每 4 拍读一次编码器
          谷值 (CNT≈0)    →  Motor_ValleyIsr() : 取电流 → 电流环 → (分频) 速度环/位置环 → 写占空比
```

| 环 | 频率 | 代码 | 分频 |
|---|---|---|---|
| 电流环 | 20 kHz | `Foc_Run()`（`foc.c:157`） | `CUR_LOOP_DIV = 1` |
| 速度环 → Iq 给定 | 1 kHz | `motor.c` TORQUE/VELOCITY/POSITION 分支 | `SPD_LOOP_DIV = 20` |
| 位置环 → 速度给定 | 200 Hz | 同上，`tick % POS_LOOP_DIV` | `POS_LOOP_DIV = 100` |
| 编码器读数 | 5 kHz | `Enc_PollIsr()` | `ENC_READ_DIV = 4` |

分频在编译期用 `typedef char` 数组卡住（`motor.c:14-16`）：三个分频不互相整除就编译不过，
免得上电后相位慢慢漂。

主循环（`main.c:97`）只剩三件事：收命令、10 ms 采一次母线、看 nFAULT。**它再怎么卡都不影响环路。**

## 3. 相电流怎么采（这块最容易画错，逐条写清）

### 3.1 为什么只能在"峰值"采

`TIM_OCMode_PWM1` + 中心对齐 1（`drv8316c.c:60,65`）：OCxREF 在 `CNT < CCR` 时为高，
于是**高边导通段以谷值为中心**，低边导通段就以**峰值为中心**。

DRV8316C 是**低边 sense-FET + 内部 CSA**（`board.h:42-52`），只有低边导通的那段 SOx 才反映相电流。
所以：**峰值 UEV 起转换，谷值 UEV 取数**（`isr.c:32-33` 按 `CNT` 判峰值/谷值，不按 DIR —— 旧工程
2026-10-14 按 DIR 判反过，结果每周期都在谷值起转换，三相电流恒 0）。

### 3.2 时间够不够（算术，已核对容量）

- `ADCCLK = PCLK2/8 = 12 MHz`（`csense.c:43`）
- 注入组采样时间 `ADC_SampleTime_CyclesMode1 = 7.5` 周期（`SRC/Peripheral/src/ch32l103_adc.c:464`），
  12 位转换 12.5 周期 → 每路 `(7.5+12.5)/12MHz = 1.667 µs`
- 三路顺序扫（A→B→C）合计 **5.0 µs**

峰值处低边窗口 = `(1-d)·Ts/2 = (1-d)·25 µs`。要求 `(1-d)·25 > 5` → **d < 0.80**。
`CS_DUTY_RECON_TH = 0.79`（`board.h`），超过就用 `ia+ib+ic=0` 把那一相补出来（`foc.c:97-109`）。

> 旧工程写的是 0.842（对应 3.95 µs），比三路转完需要的 5.0 µs **短**；这一版按推导改成 0.79。

### 3.3 标度

`0.3 V/A`（GAIN 悬空，`board.h:44,50`）→ `3.3/4096/0.3 = 2.686 mA/LSB`，满量程 **±4.667 A**（算术值）。
零点不用 1.65 V，**上电时 DRV 没使能、相电流为 0，实测标定**（`main.c:82` → `CS_CalZero()`，
64 次平均）。现场可用 `CZ` 重标。

上电自检：`CS_Init()` 软件起一次注入，看 `JEOC` 与三个 `JDR`（`csense.c:78-97`），
banner 里打 `selftest jeoc=1 ok=1`。**这一条不通，后面全是假的。**

## 4. 电角度怎么来

编码器是 MT6701（14 位，16384/圈，SSI 软件打）。20 kHz 里塞不下 32 个时钟，所以：

```
5 kHz: Enc_PollIsr() → dmech（机械增量）→ theta_e_meas += dmech·极对数；omega_e 一阶低通
20 kHz: theta_e = theta_e_meas + omega_e·(0.5·Ts + enc_poll_age·Ts + 0.5·Ts)
```

- 前一个 `0.5·Ts`：读数发生在**峰值**（半个周期处），不是谷值
- `enc_poll_age`：距上次读数过了几个谷值拍
- 后一个 `0.5·Ts`：这一拍算出的占空比写在预装载里，**下一个峰值**才真正生效

`enc_poll_age` 最大 3（每 4 拍读一次）→ **外推窗口最长 200 µs**。电角速度噪声按 §5 的估计
（±21 rad/s 电）折算到角度只有 4 mrad 级。

用**增量累加**而不是 `mech·pp` 再取模：多圈之后 `mech` 很大，乘完取模会掉精度（`motor.c:252-257`）。

### 4.1 速度估计的噪声与等效窗口（设计值，未实测）

- 5 kHz 下 1 个编码器 count / 200 µs = **1.92 rad/s 机械**
- `OMEGA_LP_ALPHA = 0.10`（`motor.c:23`）→ 时间常数 `-Ts/ln(0.9) = 1.9 ms`，
  噪声标准差不大于 `1.92/√12 × sqrt(0.1/1.9) ≈ 0.13 rad/s`（均匀量化噪声，算术估计）
- 与旧固件 5 ms 窗口的 0.077 rad/s 同量级，但**更新率是 5 kHz 且没有台阶**
- 抖不抖要按**轴位扫**判（旧工程踩过单点结论错），方法见 §9

## 5. 电流环

```
Id_ref(=0) ──► PI_d ──► Vd ──┐
                              ├─► 反 Park ─► 中点注入 SVPWM ─► 占空比
Iq_ref     ──► PI_q ──► Vq ──┘
```

- **增益**（零极点对消）：`Kp = L·ωc`、`Ki = R·ωc`，`ωc = 2π·200 Hz`
  → 默认 `Kp = 1.2566 V/A`、`Ki = 8.42e3 V/(A·s)`（由 `board.h` 的 R=6.7 Ω / L=1 mH **假设值**算出，
  **L 没实测**）。用 `RL<ohm>,<mH>` 按实测值重算。
- **电压圆分配**：先算 `Vd`，Vq 的上限取 `sqrt(Vlim² - Vd²)`（`foc.c:194-200`），
  保证合成矢量不出线性调制区。`Vlim = 0.95·Vbus/√3`（`foc.c:66`）。
- **抗饱和**：`PI_RunLim()` 输出钳位时把积分反算成 `clamp - Kp·err`（`pi.c:20-23`）。
  旧固件的速度环积分**没有**回算（`foc_pid.c:144-158`），饱和后要靠时间泄掉。
- **反馈不加低通**（`foc_lpf_alpha = 0`）：电流环自己就能吃掉 PWM 纹波，多一个滤波只多相位滞后。
  现场噪声大再开。
- **采样链断了怎么办**：`CS_Valid()==0` 时清积分、出零矢量（`foc.c:168-176`）。宁可不出力，不猜。

## 6. 速度环与位置环

- **速度环 → Iq 给定**（`motor.c` 1 kHz 分支）：`Iq_ref = PI(vel_ref - omega_m)`，输出限幅 `±i_limit`（默认 2.0 A）。
  默认 `Kp = (i_limit/vel_limit)·(bw/3) = 0.333 A/(rad/s)`、`Ki = 62.8 A/(rad/s²)`（bw = 30 Hz，**设计起点**）。
- **速度给定斜率限幅**：`accel_limit` 默认 `20·vel_limit = 1200 rad/s²`，起步不硬冲。
- **位置环 → 速度给定**（200 Hz 分支）：纯 P，`vel_ref = pos_kp·err`，`pos_kp` 默认 20 1/s，
  误差先限一圈（`POS_ERR_LIMIT_RAD`），输出限 `±vel_limit`（默认 60 rad/s）。
- **力矩模式**：`Iq_ref = iq_cmd`（限 `±i_limit`），速度 PI 每拍清一次积分，切出去不会带着旧积分。

## 7. 对齐（`A` 命令）

1. 电角度**固定 0**，`vd` 从 0 爬到 `v_align`（2.5 V）用 200 ms，再保持 `align_ms`（800 ms）
   → 转子被拉到 d 轴（`Foc_RunVolt(0, vd, 0)`）
2. 结束时把 `theta_e_meas = 0`、`Enc_SetMechZero(0)` → 电角度零点与机械零点**同时**落在这里
3. 极对数一变（`PP<n>`）`aligned` 立即作废，必须重跑 `A`

`2.5 V` 沿用旧工程 2026-09-19 的结论（1.0 V 时转子跟不上扫场），出处见旧 `board.h`。

> **未验证**：编码器安装方向（`ENC_DIR = +1`）与相序（A=CH3/PB0、B=CH2/PA7、C=CH1/PA6）。
> 方向反了不会报错，只会正反馈飞车 —— 所以第一次上电必须走 §9 的顺序，先 `M5` 开环。

## 8. 保护（按"来得及"排序）

| 保护 | 门限 | 动作 | 代码 |
|---|---|---|---|
| 相电流过流 | `MOTOR_OC_TRIP_A = 4.0 A`（设计值，采样链满量程 4.667 A 留余量） | 立即撤 EN、桥高阻、`fault_code=1`；**闭环、对齐、V/f 三条路都在内** | `foc.c:122`（`Foc_MeasureCurrent()`，`Foc_Run` 与 `Foc_RunVolt` 共用）→ `motor.c:492` `latch_fault(1)` |
| 8316C nFAULT | 芯片自己的（OCP 在 10A 档，手册表 8-1） | 主循环查 → `Motor_SetFault(2)` + 失能 | `main.c:115-123` |
| 采样失步 | 连续 64 拍"谷值到了还没 JEOC" | 撤 `valid` → 不出力 | `csense.c:127`，`CS_SYNC_MISS_RUN_MAX` |
| 模式号越界 | `M` 后面的数不在 0..5 | 忽略 | `motor.c` `Motor_RequestMode` |

**故障没清（`X`）之前 `e` 不会再放桥**（`motor.c` 使能分支里的 `motor.fault` 判断）。

> 为什么自己再做一道 4 A：8316C 的 OCP 最小档是 10 A，这台 MY-4621F 撑不到那一步。
> 这一条是"配错方向/极性时唯一来得及的保护"，不是正常运行时的限流（正常限流是 `i_limit`）。
>
> 这道判决**放在 `switch(motor.mode)` 之后**，所以对齐（`A`）和 V/f 开环（`R<v>,<hz>`）也在里面 ——
> 开环这一路本来没有电流反馈，相序配错时电流会一路涨到 8316C 的 10 A OCP 才断，那时桥和电机都已经被打过了。
> 代价：对齐电压定得过高、电机电阻又很小时，对齐本身也可能被判成过流。真遇到，先用 `VA<v>` 把对齐电压降下来。

## 9. 跟 AT32M416（mclib）是什么关系

**照搬的是结构，不是代码。**

| 照搬 | 不照搬 | 原因 |
|---|---|---|
| PWM 周期中断里跑 FOC | `mc_foc_kernal.a` | ARM EABI 静态库，链不进 RV32 |
| 速度环 → Iq → 电流 PI → Vd/Vq → SVPWM | Q15 定点全局结构体 | 那套是给带 FPU 的 M4F 写的；这里软浮点够不够用要先量（§10） |
| `foc_vq_limitation` 的电压圆分配 | 默认 PID 数值（霍尔例程、默认开环） | 那些数没在这颗电机上验过 |
| 三层节拍（电流/速度/位置） | — | — |

## 10. 已知风险 / 未验证（上板第一件事就是量这些）

1. **软浮点够不够 20 kHz**：CH32L103 是 RV32IMAC，**没有 FPU**，`Foc_Run()` 里的浮点是软件模拟。
   50 µs 一拍能不能容下，**只能上板量**：`?` 里的 `isr=..us(max ..us)` 是谷值中断耗时、
   `pk=..us(max ..us)` 是峰值中断（含读编码器）。判据：`max` 长期贴近 50 µs 就要降频或改定点。
2. **`ENC_HALF_NOP = 4`**（`enc.c:11`）只是按 96 MHz 粗略估的半周期（百 ns 级），**没上示波器**。
   若 `Q` 里 `enc_err` 一直涨，加到 8 再试。
3. **电流极性**（`CS_SIGN_A/B/C = +1`）和**编码器方向**（`ENC_DIR = +1`）**都没实测**。
4. **`CUR_L_H_DEF = 1 mH` 是假设值**，电流环增益要按 `RL<实测R>,<实测L>` 重算。
5. 母线默认 24 V；`Foc_SetVbus()` 由主循环 10 ms 一次从分压实测更新，母线没起来时按 24 V 算。
